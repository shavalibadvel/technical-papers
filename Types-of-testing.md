# Types of Testing

## Functional Testing
Verifies that each function of the software application operates in confirmance with the requirement specification. It focuses on user ations rather than how code is doing that just check what requirements asked with input provided.

## Non-Functional Testing
Evaluates the non-functional aspects of an application such as performance, usability, reliability, and security. It checks how well the system performs under specific conditions rather than what the system does.

## Smoke Testing
It is like just checking all functionalities just working or breaking even one breaks it will go through building stage to try again without checking others.

## Sanity Testing
A narrow, focused subset of regression testing conducted after receiving a software build with minor code changes or bug fixes. It quickly verifies that the specific changes work as expected without breaking related features.

## Regression Testing
Re-running existing functional and non-functional tests to ensure that recent code changes, updates, or bug fixes have not adversely affected existing features. It maintains overall software stability across continuous development cycles.

## Retesting
Testing a specific functionality or test case again after a reported defect has been fixed by the development team. Its sole purpose is to confirm that the original bug is completely resolved.

## Integration Testing
Combines individual software modules and tests them as a group to expose defects in the interfaces and interactions between integrated components. It ensures seamless data flow and communication across different parts of the system.

## System Testing
Conducted on a complete, fully integrated software product to evaluate the system's compliance with its specified requirements. It validates end-to-end user scenarios in an environment that closely mirrors production.

## Acceptance Testing
The final phase of testing performed to determine whether the software meets business requirements and is ready for delivery. Often executed by end-users or clients , it validates real-world workflows before go-live.

## Exploratory Testing
An unscripted, simultaneous learning, test design, and test execution approach where testers actively explore the application on the fly. It relies on tester intuition, domain knowledge, and creativity to uncover unexpected edge-case defects.

## Compatibility Testing
Checks whether the software application renders and functions consistently across different browsers, operating systems, devices, screen resolutions, and network environments. It guarantees a uniform user experience regardless of the user's setup.

## Usability Testing
Evaluates how easy, intuitive, and user-friendly an application is by observing real users attempting to complete typical tasks. It identifies navigation bottlenecks and design flaws to improve overall user satisfaction.
